site: 471 dead card links, dead CJK CSS, a 2:1 switcher, and headers nobody served

Four visitor-visible defects and the gates that would have caught them.

The 471 source links. library.json said "./source/<slug>.md", app.js rendered
it verbatim, and site/dist/source/ held nothing -- so every card on every
locale linked to a directory that did not exist. The files were real all along:
upstream/.../references/shots/ has all 157 of them, 575 KB, laid out as
<category>/<slug>.md. So they are shipped rather than the link removed, with
sourceUrl rewritten to the real relative path. It is "../source/", not
"./source/": the base is the *page*, one level down from the root, and getting
that wrong is how the first attempt still dangled on all 471 with the files
present. check_dist.py now resolves every URL in the payload from the
directory of the page that renders it -- the runtime-URL check cannot see these,
because they arrive as data rather than as a string literal in a script.

Dead language CSS. seo.py wrote <html lang="zh-Hans"> from its own table while
the Chinese home page carried six html[lang="zh-CN"] rules governing CJK
letter-spacing and padding. All six were inert, on the one page whose language
they exist to correct. Two tables held the same fact; seo.py now imports
build_site.META instead of restating it, and check_seo.py compares the
attribute against that one table rather than asserting it is merely not "en",
which is true of both spellings and so caught neither. check_dist.py also
asserts every html[lang=] selector in the tree names a language the build
emits, so dead CSS fails a build.

The switcher was 2.03:1 in the light theme. It set a hardcoded *dark* pill,
background: rgba(14,14,12,.35), next to color: var(--muted) -- the light
theme's grey. A hardcoded colour cannot follow a theme, and pairing it with a
themed colour is how it survived a palette where every token carries a comment
stating the ratio it clears. It now uses var(--surface)/var(--text) like the
other topbar controls: 16.30:1 light, 14.10:1 dark, both measured by
check_dist.py out of the built stylesheet rather than asserted. The generated
block is delimited by sentinels so the gate audits our CSS and not upstream's
1800 lines, and every custom property it references must exist in *both*
themes.

_headers was at the repository root, which governs nothing: Cloudflare reads it
from the published directory, so the site shipped with the host's defaults -- no
CSP, no nosniff, no immutable on 128 MB of video. build_site.py copies it and
validates it. Its /media/* rule had a leading space, which made it not a path
rule at all: the one entry governing the video was the one that silently did not
apply. The format check distinguishes the two kinds of line by shape rather than
indentation, because 14 of the 22 lines are correctly indented headers --
check_headers.py pins that with three negative cases (including the shipped bug)
and six positive ones.

legacy() never added the page's locale to its fallback chain:
if (DATA.locales[locale]) indexes an *array* by a string, so it is always
undefined and every locale got the fallback dictionary. check_i18n.js boots the
built bundles under node and asks.

Stated plainly, because it is easy to overstate: nothing a reader saw was wrong
from that last bug. app.js reads chrome through s('ui', key), which was always
right -- confirmed by running all 119 browser assertions against the broken
build and watching them pass. Part of this session was spent reading an English
chrome in a browser tab that had not executed its JavaScript at all, and
mistaking it for a site defect. legacy() fed only the zh/en card tables, which
are zh and en on every locale. It was a silently wrong code path, not a visibly
wrong page, which is the harder kind: no symptom to grep for, until something
reads legacy().ui and every locale turns English in one release.

Also: check_seo.py imports HTML_LANG rather than restating it; init.ps1 gates on
an optional per-gate interpreter, since one gate is node; ck() takes a lazy
detail, after a version that indexed a list inline and crashed on the *passing*
tree.

Known and NOT fixed: selftest.py's deep-link scroll check fails intermittently
(observed top=277 and top=513 against a bar of |top| < 200, and one clean pass).
app.js scrolls once when loadLibrary() resolves, while the library is still
settling, so the landing point drifts. Loosening the bar would hide it.
